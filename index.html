Client work Live 2026

JVD Dental Clinic

Marketing and online-booking site for a dental clinic with two locations in Gostivar.

A React single-page app built on Vite 6 and Tailwind CSS v4, with appointment booking delegated to an embedded Cal.com calendar so the site never touches patient data itself. Every clinic, practitioner and phone number lives in one data file — adding a new location or dentist needs no changes anywhere else, because each page derives its layout from the length of those lists. A validator runs in development and fails loudly if a doctor is wired to a location that does not exist, which is the one mistake that would silently hide someone from the booking page.

  • Tailwind v4 configured entirely from CSS — design tokens live in an @theme block, no tailwind.config.js
  • React and the router split into a separate vendor chunk so app edits do not bust the cache for returning visitors
  • First paint of the homepage is ~87 kB gzipped; the whole four-page app is under 15 kB of that
  • Cal.com embed loaded on demand, only once a patient reaches the booking page
  • Self-hosted variable font — no Google Fonts request, no third-party cookie surface
  • No component or icon library: every icon is an inline SVG, every component local JSX
React 19 Vite 6 Tailwind CSS v4 React Router 7 Cal.com ESLint 9 Vercel

ACPV CANN

Trade site for ACPV DOO, a licensed medical cannabis producer supplying European distributors from Beloviste, Gostivar.

A business-to-business site aimed at a regulated audience, so the whole thing is organised around proof: certificates of analysis, ISO 9001 and ISO 14001 documents, GACP certification and the API authorisation are all downloadable straight from the pages that reference them. Six static pages, no framework and no build step — the only server-side code is one Vercel function that delivers the trade-enquiry form over SMTP.

  • Serverless contact endpoint written provider-agnostically: SMTP host, mailbox and recipient all come from environment variables
  • Form handler validates required fields, caps input length, escapes HTML, and strips line breaks to block email header injection
  • Honeypot field silently absorbs bots without showing them an error
  • Sender address is always the owned mailbox with the enquirer in Reply-To, so providers never reject the message
  • Security headers set in vercel.json: HSTS, nosniff, frame options, referrer and permissions policy
  • Clean URLs plus a year-long immutable cache on images, fonts and certificates
HTML5 CSS3 JavaScript Vercel Functions Node.js Nodemailer Python

Durmisi&Clean

Bilingual German/English site for a family-run cleaning company in Rafz, Switzerland.

Six static pages covering services, about, contact and a Swiss-law Impressum — plain HTML, CSS and JavaScript with no dependencies and no backend. The German text is written literally into the HTML rather than injected at runtime, so the page is correct and indexable with JavaScript switched off; the English translation swaps in from a single strings file. Contact details live in one object at the top of that file, so the owner changes their phone number once and it updates the header, footer, contact page, Impressum, mobile call bar and the form recipient.

  • Language toggle persists in localStorage and applies before first paint, so an English visitor never sees a flash of German
  • Attributes translate too — placeholders, alt text, <title> and the meta description
  • Any contact value left as a [PLACEHOLDER] is detected at runtime and its icon dropped, so the site can never ship a dead link
  • Contact form validates in the active language, then hands off to the visitor’s mail client with a structured message
  • Keyboard accessible throughout: skip link, focus trap in the mobile menu, Esc to close, visible focus rings, WCAG AA contrast
  • No cookies, no analytics, no third-party requests — everything served from one folder
HTML5 CSS3 JavaScript i18n Schema.org Vercel

DGDsmart

Single-page site for my own computer store and electronics repair service in Gostivar.

DGDsmart sells hardware and repairs electronics, so the site serves two audiences at once and the design system splits them by colour — blue and cyan for the store, amber for the workshop. Plain HTML, CSS and JavaScript, no build step. Everything derives from CSS variables in :root, so changing one value restyles the whole site.

  • Tabbed repair catalogue, with price and turnaround fields deliberately left out until they are accurate
  • Repair form with no backend: it validates, then opens WhatsApp or the visitor’s mail app with the details pre-written

Full-stack · Security 2025 — 2026

Authentication System

A complete authentication and authorisation stack written from scratch for the Information Security course at FINKI.

Rather than pulling in an auth library, every step is implemented and therefore visible: registration with strength rules, bcrypt password hashing, one-time codes by email, server-side sessions, permission checks per resource, and a working certificate authority. An Express API backs a React 19 client; user records are kept in a local JSON file because the point of the exercise is the security model, not the database.

  • Email two-factor authentication — a one-time code issued on login and delivered through Nodemailer
  • Role-based access control with three roles mapped to explicit permission sets, checked per resource
  • Just-in-time privilege elevation: temporary access granted for a chosen duration and revocable on demand
  • X.509 certificate hierarchy generated with node-forge — a root CA that signs downloadable child certificates
  • HTTPS server that runs against the certificates it just generated
  • Admin panel for inspecting users and reassigning roles at runtime
Node.js Express React 19 bcrypt node-forge Nodemailer REST
